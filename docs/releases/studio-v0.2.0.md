# Studio 0.2.0 版本说明与验收记录

> 版本：`0.2.0`（tag `studio-v0.2.0`）
> 发布日期：2026-11-09
> 定位：独立 Studio 的**文档与项目可靠性**。把「项目会丢、会坏、升级就废」这类
> 风险收口，形成可靠闭环。
> 相关文档：`project-progress-and-version-roadmap.md` §5、`current-project-status.md`、
> `storage-layout.md`、`backup.md`

## 1. 这个版本交付了什么

`0.2.0` 的范围是：冻结文档格式的连续迁移、统一 Web 与文件系统两个仓库的契约、
完成项目导入的版本检查与冲突策略、备份与恢复报告、明确自动保存 / 日志裁剪 /
存储配额策略。按路线图，这一版的成果是**可靠性**：数据不该悄悄消失，升级不该
毁掉旧项目，出问题要能看懂发生了什么。

- **文档格式迁移链冻结**：`CURRENT_SCHEMA_VERSION` + `MIGRATIONS` 步骤表 +
  `migrateDocument()` + `detectSchemaVersion()`。当前文档格式 **v4**，v1→v4 连续
  升级；迁移失败抛 `MigrationError` 并**保留原始数据**，成功则把迁移记录写进
  文档自带的 `migrations` 历史。高于当前版本或缺少版本号的文档一律拒绝——不猜
  版本。
- **仓库契约统一到一个入口**：`design-persistence/src/contract.ts` 定义
  `ProjectRepository` 接口、`ProjectNotFoundError`、快照与事务语义；
  `loadDocumentPayload()`（迁移 + 校验）、`replayJournal()`（统一的重放与降级
  判定）、`assertSavableDocument()`、`normalizeAssetHash()` 由两个后端共用，因此
  行为不会因为换了存储而改变。**两个后端跑同一套契约测试**（快照往返、重放、
  断档降级、项目列表、删除、日志裁剪、资产去重、旧版本迁移）。保留策略统一为
  最近 10 份快照 + 200 条事务，另有 `pruneJournal()` 主动裁剪。
- **存储布局也有独立的迁移链**：`storage-layout.ts` 提供
  `CURRENT_STORAGE_VERSION` + `STORAGE_MIGRATIONS` + `migrateStorageLayout()`，
  与文档格式同一套纪律（单一版本来源、逐级升级、未来版本拒绝、迁移历史）。
  文件系统后端在打开项目时升级 manifest，并把原始文件备份到
  `backups/manifest-v{旧版本}.json`；浏览器后端把布局版本记进新增的 `storage`
  meta 表，旧库当成 v1 逐级升到 v3。规格见 `storage-layout.md`。
- **自动保存**：事务日志即时写入（恢复的依据），快照合并写入（停止输入 800ms
  后落盘，连续几次编辑只写一份），顶栏实时显示「待自动保存 / 自动保存中 /
  已自动保存 / 自动保存失败」，页面关闭或切到后台时立即冲刷待写快照；存储配额
  耗尽会被识别并单独提示（提示导出 JSON 备份），不会被当成普通异常吞掉。
- **导入的版本检查与冲突策略**：旧格式文件升级后导入并提示来源版本，更高版本
  文件明确拒绝；导入文件与本地项目 id 相同时，让用户选择覆盖原项目或作为新
  项目导入；只重名（id 不同）时弹输入框让用户自己起名，默认预填「原名（2）」，
  校验挡住空名字与重名。**批量导入**支持多选，一律按新项目导入、不覆盖任何现有
  项目，程序先按现有项目和批内名字去重，再弹一张可编辑的确认表让用户逐个改名；
  坏文件单独记为失败，不拖垮整批。
- **图片资源闭环**：新增 `asset.upsert` 与 `image.patch` 两条领域命令；插入图片时
  字节先按 SHA-256 落库，节点创建与资源登记在**同一个事务**里；导入或打开项目
  时逐份核对资源是否在本地，缺失数量与名字写进状态提示和恢复报告。资源面板列出
  大小、引用数和缺失状态；缺失资源可用原文件重新关联（校验内容哈希，只补字节
  不改文档，revision 不变），未引用资源可清理；「替换图片…」把新图落库并在同一
  事务里改指向，节点 id、位置、尺寸与 `fit` 全部保持不变。
- **存储用量视图**：读取 `navigator.storage.estimate()`，显示已用 / 额度 / 百分比
  与进度条，70% 提示、90% 告警，并提示导出 JSON 与清理旧项目这两条出路。
  仓库契约新增可选能力 `inspectStorage()` 与 `trimSnapshots()`，文件系统按磁盘真实
  字节、浏览器按序列化 UTF-8 长度估算（同一口径，两个后端可比）；后端不支持统计
  时显示「无法统计」，不把 0 当成「不占空间」。
- **自动备份与轮转**：独立 IndexedDB 库按项目保留最近 3 份完整文档备份，落盘后
  每 10 分钟最多写一份；可下载为 JSON，也可走 `history.restore` 还原（可再撤销）。
- **恢复报告**：打开项目后逐行列出「恢复自哪一版、重放了多少条事务、最新已知
  修订、文档格式版本与降级状态」，并可导出为 JSON。
- **历史版本列举与回滚、事务级回退**：仓库契约新增 `listSnapshots()` /
  `readSnapshot()`，两个后端都能列出保留的多个版本并读回任意一版；还原走运行时
  自带的 `history.restore` 命令，revision 继续单调递增、事务日志留痕，因此这次
  还原本身还能再撤销回去——不覆写存储，也就不会清掉日志或让版本号倒退。操作历史
  面板把事务日志列成可读步骤，可回退到任意一条事务之后的状态；目标没有快照时
  按「不晚于目标的最近快照 + 顺序重放」重建，重建不写存储。每个项目额外保留一份
  **永不被裁剪**的重建基线；裁日志之前先把「新的日志起点前一版」重放出来固化成
  新基线，裁剪因此始终安全。
- **磁盘备份**：自动保存落盘后按 5 分钟节流，把完整文档以
  `ufira-backup-<项目>-<时间戳>-r<revision>.json` 写进用户用 File System Access
  API 选的目录，每个项目保留最近 10 份；目录句柄存 IndexedDB 跨会话恢复，
  权限只能查询、需要手势时再申请；不支持该 API 的浏览器明确提示并指向导出 JSON。
  规格见 `backup.md`。
- **备份加密**（本版本新增）：`studio-web/src/backup-crypto.ts` 提供加密信封——
  PBKDF2-HMAC-SHA256（210000 次迭代）派生密钥 + AES-GCM-256 加密整份文档，
  每个文件用新的 salt 与 IV，迭代次数写进信封（将来调高不会让旧文件解不开）。
  加密是面板上的**显式开关**，通过 `BackupContentEncoder` 端口接进执行器。
  **密码不落盘**：只存在会话内存里，没有服务端就没有找回通道，忘记即永久丢失。
  单个文件导入时识别信封并要密码（错可重试），批量导入明确拒绝加密文件。

## 3. 可复现的人工验收清单

按顺序执行，每步记录「通过 / 不通过 + 现象」。重点是**可靠性**路径：

1. **迁移**：拿一份 `0.1.x` 时代的项目 JSON 导入 → 提示已从格式版本 N 升级到当前
   版本 → 内容与原项目一致；拿一份更高版本的文件导入 → 被明确拒绝。
2. **导入冲突**：导出当前项目 JSON → 改名字再导入 → 弹重名输入框（默认预填
   「原名（2）」）；用**同一个 id** 的文件导入 → 弹「覆盖 / 作为新项目」选择，
   选覆盖后原项目内容被替换，选新项目则多出一个副本。
3. **批量导入**：一次拖入 3 个 JSON（其中一个内容损坏） → 弹确认表可逐个改名 →
   坏文件单独报失败，其余照常导入；批量不覆盖任何现有项目。
4. **刷新恢复**：编辑若干次 → 等顶栏「已自动保存」→ 刷新 → 内容与 revision 保持
   → 「历史 → 恢复报告」逐行可读且能导出 JSON。
5. **事务级回退**：连续做 10 次编辑 → 「操作历史」回退到第 3 步 → revision 继续
   递增 → 再撤销可回到最新；早期的步骤如果标「无法回退」，说明它早于基线窗口。
6. **存储用量**：「数据」面板显示总配额与按项目拆分的占用 → 执行「裁历史版本」
   → 占用下降；接近配额时出现 70% / 90% 提示。
7. **磁盘备份**（Chromium）：数据 → 磁盘备份 → 选一个空目录 → 确认写出
   `ufira-backup-*.json`；5 分钟内再保存不重复写；「立即备份」立刻写；超过 10 份
   时最旧的被删；刷新页面后目录仍在、上次备份时间仍在；清空浏览器存储后目录里的
   文件仍在。
8. **备份加密**（Chromium）：在磁盘备份面板设置密码并启用加密 → 立即备份 → 用
   文本编辑器打开该文件，看到的是 JSON 信封（`format: ufira-encrypted-backup`）
   而不是文档内容 → 把它拖回编辑器导入，会要求输入密码 → 输对则内容完整，
   输错则提示「密码不正确，或备份文件已损坏」→ 关掉页面重开，密码需要重输。
9. **缺失资源**：导入一个含图片但没有资源字节的项目 → 资源面板标出缺失 →
   用原文件重新关联 → 校验通过后图片出现，revision 不变。

## 4. 已知限制

- **迁移只升不降**：用旧版本应用打开新文档会被拒绝（刻意的保护）；应用版本回滚
  不在本版本承诺范围内，存储布局的回滚要由旧版本应用自己处理。
- **备份加密没有密钥找回**：密码不落盘，忘记即永久丢失。加密是**显式开关**，
  已经写出的明文备份不会被追溯加密。
- **跨设备自动同步：明确搁置**（2026-11-09 决定本轮不做）。依赖用户自己的同步盘；
  没有账号、没有服务端。将来要做需要先定通道选型（WebDAV / 自建服务端 / 只做
  同步盘约定），届时单独立项。
- **磁盘备份只在 Chromium 系可用**（File System Access API）；Firefox / Safari 上
  面板明确提示不支持并指向「导出 JSON 备份」。
- **定时后台备份没有做**：只在自动保存真正落盘后触发，页面关闭时不会为了备份
  而阻塞。
- **存储用量是估算**：文件系统按磁盘真实字节，浏览器按序列化 UTF-8 长度估算；
  两者口径不同，不可直接横向比较。

## 5. 数据丢失风险（必须告知使用者）

1. **浏览器存储会被清掉**：清空站点数据、隐私模式退出、配额回收都会带走项目。
   → 用 JSON 导出或磁盘备份；两者都建议定期做。
2. **加密后忘记密码 = 永久丢失**：没有服务端就没有找回通道，这是加密的代价。
3. **IndexedDB 自动备份只有最近 3 份、10 分钟节流**；磁盘备份 10 份、5 分钟节流。
   两者都挡不住「备份目录本身被误删」。
4. **迁移失败不会毁数据**：`MigrationError` 抛出时原始数据仍在，但需要用户自己
   处理（导出旧格式文件或回退应用版本）。
5. **AI 计划不落盘直到确认**；确认前关闭页面不会留下半套改动。

## 6. 浏览器支持范围

| 浏览器 | 编辑器 | 磁盘备份 / 加密 | 备注 |
| --- | --- | --- | --- |
| Chrome / Edge（Chromium 109+） | ✅ | ✅ | 推荐；File System Access API + WebCrypto |
| Firefox | ✅ | ❌ | 面板会明确提示不支持并指向导出 JSON |
| Safari 16.4+ | ✅ | ❌ | 同上；`storage.estimate()` 可能返回粗略值 |
| 移动端浏览器 | ⚠️ 未验收 | ❌ | 触控与窄屏未做专门适配 |

加密依赖 WebCrypto（`crypto.subtle`）：不支持的环境在面板上直接说明，而不是给一个
点了没反应的按钮。

## 7. 升级与回滚

- 文档格式：**v4**（v1→v4 连续迁移，迁移历史写进文档）。
- 存储布局：文件系统 **v2**、浏览器 **v3**（`storage-layout.ts`；旧项目打开时自动
  升级，原始 manifest 备份到 `backups/manifest-v{旧版本}.json`）。
- 项目内容回滚走 `history.restore`（revision 递增、可再撤销）；事务级回退走
  操作历史面板。
- 应用版本回滚不在本版本承诺范围内。

## 8. 不在本版本承诺内

跨设备自动同步（明确搁置）、加密备份的密钥找回、存储布局降级、React/PDF 导出、
实时协作、插件生态、正式安装包。
