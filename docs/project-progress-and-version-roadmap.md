# AI Design Studio 项目进度与版本路线图

> 文档状态：生效中的版本与进度基线  
> 基线日期：2026-11-06  
> 当前 Studio 开发版本：`0.1.0`  
> 当前阶段：Phase 0 原型验证，尚未发布可供生产使用的独立应用（`0.2.0` 文档与项目可靠性已开工）

## 1. 文档目的

本文把项目进度、功能范围和软件版本建立为一一对应关系。今后的功能开发、验收、发布说明和版本号调整均以本文为基线。

本文只描述独立 **AI Design Studio**。仓库中 `packages/core`、`packages/tunnel`、`packages/adapter-figma`、`schema` 和 `plugin` 属于停止发展的 Vibma MCP-to-Figma legacy bridge，其 `1.1.5` 版本不计入 Studio 版本，也不得用来判断 Studio 的完成度。

## 2. 版本口径

### 2.1 Studio 版本的唯一含义

- Studio 使用语义化版本 `主版本.次版本.修订版本`。
- `0.x.0` 是功能里程碑；只有对应版本的必需项和发布门槛全部通过，才能把状态改为“已完成”。
- `0.x.y` 是该里程碑内的缺陷修复或兼容性修订，不新增跨里程碑的大功能。
- `1.0.0` 表示本文定义的 V1 产品闭环达到稳定发布标准；在此之前均不承诺生产稳定性。
- 所有 Studio workspace 包原则上使用同一个产品版本。内部包若暂时保持独立版本，发布时仍必须由根级 Studio 版本清单记录它们的精确组合。
- Git tag 使用 `studio-vX.Y.Z`，避免与 legacy Vibma tag 混淆。

两张状态列必须分开看：`发布状态` 使用第 6 节的状态词，只有版本说明和
`studio-vX.Y.Z` tag 齐备才能记为“已完成”；`实现进度` 只描述代码里已经存在多少，
不构成发布日期承诺。此前该表把 `0.4.0` 之后的版本一律标成“规划”，与各节
“本轮已完成的部分”互相矛盾，读表的人因此无法判断距离 `0.10.0` 还有多远。

“规划”只表示版本目标，不能视为已实现或已承诺交付日期。版本完成度以验收项和证据为准，不按提交数量或界面观感估算。

## 4. `0.1.0`：独立 Studio 垂直原型

### 4.1 已实现

领域与数据基础：

- 判别联合的设计节点、页面、token、组件和资产文档模型，以及字段级 Schema 校验。
- 节点、文本、页面、token 和组件等领域命令。
- 原子事务、revision、快照、事务日志、撤销/重做和崩溃恢复原型。
- 文件系统仓库与浏览器 Dexie/IndexedDB 仓库；二进制资产按哈希存储和校验。

布局、渲染与导出：

- `absolute`/`stack` 布局，fixed/fill/hug、padding、gap、对齐和结构化 warning。
- 可注入的文本测量契约、确定性回退测量器和浏览器 Canvas 字体测量。
- HTML/CSS 与 SVG 导出；浏览器端通过 SVG 光栅化生成 PNG。
- 画布通过同一布局结果解释 stack、fill 和 hug，降低编辑与导出语义漂移。

Web 工作台：

- 本地项目创建、列表、切换、重命名、删除，以及 JSON 导入/备份。
- 页面创建、重命名和删除。
- 嵌套图层树、折叠、同级重排和拖入容器。
- 节点创建、选择、框选、多选、移动、缩放、吸附、删除、复制/粘贴、键盘微移、对齐和分布。
- 画布缩放、适应内容、行内文本编辑和布局 warning 定位。
- 属性面板支持布局、尺寸模式、间距、填充、描边、圆角、透明度、显隐、锁定和文本样式。
- 多选批量属性编辑，交互结束后以单个原子事务提交。
- 组件定义、实例化、实例物化与 override 的基础 UI。
- HTML、SVG、PNG 和项目 JSON 下载。

AI 原型：

- `SafeAiEditor` 的计划、dry-run、before/after、影响节点、warning、取消、显式确认和过期 revision 拒绝。
- OpenAI-compatible `/chat/completions` Planner、命令词汇提示、文档摘要和模型 JSON 计划解析。
- Web 端 AI 服务地址、模型和密钥设置入口，以及待确认计划界面。

### 4.2 部分实现或存在限制

- Web 工作台是可运行的垂直切片，尚未达到生产级编辑器标准。
- 画布已切到 Canvas 2D 场景渲染并有绘制耗时基线与预算门禁；子节点级裁剪与更大规模
  的虚拟化仍未做。
- 文本测量尚未建立跨平台字体基线、字体加载策略和完整缓存策略。
- PNG 依赖浏览器 SVG/Canvas 光栅化；外部图片可能污染画布，尚无独立交付流水线。
- 组件与 override 仍是受限子集：detach、slot、循环引用防护、文本/外观 override 与重置已实现，
  尚未覆盖尺寸/显隐的界面入口、组件属性暴露与批量重置。
- OpenAI-compatible Provider 已有实现，但仍需真实服务端到端验证、流式体验、凭据安全和 Provider 支持矩阵。
- 测试以单元测试和包级构建为主，缺少完整端到端、视觉回归、性能和浏览器矩阵。

### 4.3 明确未完成

- 生产级渲染器与性能保障。
- React/PDF 等后续导出格式和稳定的 PNG 交付链路。
- 完整 AI Reviewer、结构审查与多 Provider 产品体验。
- 独立 Studio MCP adapter。
- 不依赖 Figma 的完整端到端设计工作流和正式安装包。

### 4.4 `0.1.0` 完成门槛

- `npm run build:studio-core`
- `npm run test:studio-core`
- `npm run build:studio-web`
- `npm run test:studio-web`
- 关键垂直流程有可重复的人工验收记录：新建项目 → 编辑 → 撤销/重做 → 刷新恢复 → AI 预览/确认 → 导出。
- 已知限制、数据丢失风险和浏览器支持范围有明确记录。
- 创建 `studio-v0.1.0` tag 并附版本说明后，状态才能从“进行中”改为“已完成”。

## 5. 后续版本范围与验收

### `0.2.0`：文档与项目可靠性

- 范围：冻结 `schemaVersion` 连续迁移；统一 Web 与文件系统仓库契约；完成项目导入版本检查、冲突策略、备份与恢复报告；明确自动保存、日志裁剪和存储配额策略。
- 验收：迁移与恢复故障注入通过；刷新后无已确认事务丢失；`0.1.x` 项目可升级且可回滚。

本轮已完成：

- 文档格式版本升到 2，并冻结迁移机制：`CURRENT_SCHEMA_VERSION` + `MIGRATIONS` 步骤表
  + `migrateDocument()` + `detectSchemaVersion()`；迁移失败抛 `MigrationError` 并保留
  原始数据，成功则把迁移记录写进文档的 `migrations` 历史；`0.1.x` 文档可连续升级，
  高于当前版本或缺少版本的文档明确拒绝。
- 仓库契约统一到 `design-persistence/src/contract.ts`：接口、错误类型、快照校验、
  迁移入口、日志重放与降级判定只有一份实现；文件系统与浏览器两个后端跑同一套契约
  测试；保留策略统一为 10 份快照 + 200 条事务，并提供 `pruneJournal()`。
- 自动保存落地：事务日志即时写入、快照合并写入，顶栏显示保存状态，页面隐藏或关闭
  时冲刷待写快照，存储配额耗尽被识别并单独提示。
- 导入版本检查：旧格式文件升级后导入并提示来源版本，更高版本文件明确拒绝。
- 导入冲突策略：导入文件与本地项目 id 相同时，让用户选择覆盖原项目或作为新
  项目导入；覆盖走仓库的 `replaceProject`，清掉旧快照、旧日志和旧资产。只重名
  （id 不同）时弹出输入框让用户自己起名，默认预填「原名（2）」的建议名，校验
  挡住空名字与重名，不再静默沿用同名。
- 批量导入：文件选择框支持多选，一次导入多个 JSON 文件。批量一律按新项目导入、
  不覆盖任何现有项目；程序先按现有项目和批内名字去重，再弹一张可编辑的确认表
  让用户逐个改名，批内重名会被拦下。坏文件单独记为失败，不拖垮整批。
- 图片资源可插入、去重、渲染并随导出内联：新增 `asset.upsert` 与 `image.patch`
  两条领域命令，插入图片时字节先按 SHA-256 落库，节点创建与资源登记在同一个事务里；
  导入或打开项目时会逐份核对资源是否在本地，缺失数量与名字写进状态提示和恢复报告。
- 图片资源面板与重新关联：面板列出资源大小、引用数和缺失状态；缺失资源可用原文件
  重新关联（校验内容哈希，只补字节不改文档，revision 不变）；未引用资源可清理，
  新增 `asset.delete` 领域命令与可选的仓库 `deleteAsset` 能力。
- 图片整张替换：`image.patch` 支持 `assetId`，属性面板「替换图片…」把新图落库并
  在同一事务里改指向，节点 id、位置、尺寸与 `fit` 全部保持不变。
- 存储用量视图：读取 `navigator.storage.estimate()`，显示已用/额度/百分比与进度条，
  70% 提示、90% 告警，并提示导出 JSON 与清理旧项目这两条出路。
- 存储用量按项目统计 + 清理引导清单：仓库契约新增可选能力 `inspectStorage()` 与
  `trimSnapshots()`，文件系统按磁盘真实字节、浏览器按序列化 UTF-8 长度估算（同一
  口径，两个后端可比）。「数据」面板按项目列出版本/日志/资源占用与历史份数，
  并给出可直接执行的清理清单：裁历史版本（默认保留当前 + 2 份历史）、删除旧项目。
  后端不支持统计时显示"无法统计"，不把 0 当成"不占空间"。
- 自动备份与轮转：独立 IndexedDB 库按项目保留最近 3 份完整文档备份，落盘后每
  10 分钟最多写一份；可下载为 JSON，也可走 `history.restore` 还原（可再撤销），
  删除项目时一并清理。
- 恢复报告：打开项目后逐行列出恢复自哪一版、重放事务数、最新已知修订、文档
  格式版本与降级状态，并可导出为 JSON。
- 浏览器存储升到格式版本 2（新增历史快照表；IndexedDB 不允许升级时改表主键，
  因此不改主键），文件系统 manifest 记录存储版本与文档格式版本，迁移落盘前保留原始文件备份。
- 历史版本列举与回滚：仓库契约新增 `listSnapshots()` / `readSnapshot()`，两个后端
  都能列出保留的多个版本并读回任意一版（旧格式文档在读取时迁移到当前格式）；
  属性面板新增「历史版本」区块，可还原到旧版本。还原走运行时自带的
  `history.restore` 命令，revision 继续单调递增、事务日志留痕，因此这次还原
  本身还能再撤销回去——不覆写存储，也就不会清掉日志或让版本号倒退。
- 事务级回退：操作历史面板把事务日志列成可读步骤，可回退到任意一条事务之后的
  状态；目标没有快照时按「不晚于目标的最近快照 + 顺序重放」重建，重建不写存储，
  回退仍走 `history.restore`。快照保留份数从 3 提到 10，让可回退范围覆盖更多步骤。
- 重建基线：每个项目额外保留一份**永不被裁剪**的基线文档，位置落在「事务日志
  起点的前一版」。日志按条数保留（200 条）、快照按份数保留（10 份），两者不对齐，
  于是早于最老快照的那段只剩日志、没有起点可重放；有了基线，日志窗口里的每一步
  都能重建。裁日志之前先把「新的日志起点前一版」重放出来固化成新基线，裁剪因此
  始终安全；基线也不受「裁历史版本」影响。浏览器存储升到格式版本 3（新增基线表）。
  操作历史面板按真实可达性决定是否给回退按钮，回不去的步骤标「无法回退」，
  不再误标成「当前」。

本轮仍未完成：

- 存储布局版本迁移的成体系步骤（当前只有文档格式这一条链路成体系）。
- 备份只落在浏览器本地 IndexedDB：没有定时导出到磁盘、加密或跨设备同步。

### `0.3.0`：人工编辑基础闭环

- 范围：补齐稳定的选择、命中测试、组合变换、复制粘贴、图层排序和快捷键；明确锁定、隐藏、跨容器移动、多选和页面删除边界；所有持久化改动经命令总线提交。
- 验收：标准页面可在不编辑 JSON 的情况下完成创建、排版、修改、撤销、重做和恢复；关键路径端到端测试通过。

本轮已完成的部分：

- 编组与取消编组：同级多选可编成一个不带填充的 frame，包围盒按布局引擎解出的绝对盒计算，
  子节点坐标换算成相对编组；`Ctrl/Cmd+G` 编组、`Shift+Ctrl/Cmd+G` 取消编组，右键菜单
  与图层面板都有入口。两种操作各是一次原子事务，可撤销。
- 锁定与隐藏的选择语义：锁定节点画布点击穿透、框选过滤、批量移动/对齐/删除跳过并
  在状态栏说明；属性面板仍可编辑锁定节点；复制出的副本自动解锁。
- 自动布局子节点的键盘微移：stack 里 x/y 由布局引擎计算，方向键改为调整兄弟顺序
  （边界处停止），绝对定位节点仍按像素微移。
- 画布渲染与交互整体迁移到 Canvas 2D（Phase A/B/C 收尾）：DOM 节点副本、Moveable/Selecto
  旧交互层与 `?selection=dom` / `?renderer=dom` / `?hittest=compare` 三个调试开关一并删除，
  `react-moveable` / `react-selecto` 依赖移除；单击选中、拖拽/缩放、框选、吸附、双击文本
  编辑与右键菜单全部走 Canvas 命中，画布上不再有任何 DOM 节点副本，并配视觉隐藏的
  可访问性 listbox（上下/Home/End 移动并同步选中、Delete 删除、`aria-selected` 等齐全）；
- 画布工具体系（P1）：创建入口从「瞬时插入」升级为「工具模式」（选择 / Frame / 矩形 /
  椭圆 / 直线 / 多边形 / 星形 / 文本 / 抓手），图元工具可拖拽绘制，Shift 等比、Alt 从中心
  展开，松手提交一条 `node.create` 并自动回到选择工具；快捷键 `V/F/R/O/L/G/S/T/H`、
  `Esc` 回到选择。工具状态是纯视图状态，不进文档也不涨 revision；
- 形状族与矢量基础（P2）：直线/多边形/星形落地为 `vector` + 归一化 `M/L/Z` 路径
  （`design-schema/src/geometry.ts`），改宽高即缩放图形；命中按真实路径判定；SVG 输出
  `<path>`、HTML 输出内联 `<svg>`，`vector` 支持等级升为 `exact`，无 geometry 的旧文档
  导出产物不变；`AppearanceSpec.strokeWidth` 与四角独立圆角 `cornerRadii` 同时接入画布、
  导出与属性面板（四角不同时 SVG 改走 `<path>` + `A`，文档格式仍只有 M/L/Z）；
  等距分布从纯函数层接到右键菜单与多选浮出的对齐工具条。
  相位与后续计划见 `editor-tooling-roadmap.md`；
- 钢笔与曲线路径（P3.1/P3.2）：`vector` 路径支持 `C`/`Q` 贝塞尔，在曲线上的点限定在 [0,1]、
  控制点允许越界，包围盒按离散化结果计算；画布、命中、SVG/HTML 导出共用同一套几何。
  钢笔工具（`P`）支持角点/平滑点、点回起点闭合、`Enter`/`Esc`/双击结束、`Shift` 45° 约束，
  一次路径一条事务一次撤销。规格见 `pen-and-path-editing.md`；
- 矢量节点编辑（P3.3）：双击或 `Enter` 进入编辑态，拖锚点/手柄实时预览，`Alt` 断对称、
  `Shift` 约束方向、`Delete` 删锚点；松手提交一条新增的 `vector.patch` 命令，几何与布局
  写在同一条命令里（改锚点会改变包围盒，拆开会出现「盒子不含图形」的中间态）。
- 线段插点（P3.4）：编辑态点线段即插点并顺势拖动；曲线用 de Casteljau 切分，形状不变，
  直线段不生成控制点。
- 锚点类型（P3.5）：双击锚点切换角点/平滑点，不新增字段；切线取前后邻居连线、长度取 1/3，
  切换即时提交。尚未实现：多选锚点、锚点吸附、带独立手柄的尖角；
- 布尔运算（P4.1）：合并/减去/交集/排除，操作数烘焙成一条路径、结果替换操作数，
  `node.create` + `node.delete` 同一事务；基准层取 z 序最下层（Figma 语义）。算法用
  `polygon-clipping`（MIT），依赖只在 `studio-web`；结果不含曲线（输入离散成折线）。
  同时把多子路径的命中改成按环 + 非零环绕数，带洞形状的洞里不再被点中；
- 蒙版（P4.2）：`mask?: boolean` 属性裁剪同父级里排在它上面的兄弟；画布 `clip()`、
  命中 `maskedBy`、SVG `<clipPath>`、HTML CSS `clip-path:path()` 四条链路都接上。
  页面与容器的兄弟遍历共用同一套逻辑，避免页面级蒙版失效；
- 旋转（P5.1）：`layout.rotation`（角度制、顺时针为正、绕节点中心）。命中逐层逆变换、
  选择框与手柄跟随旋转、缩放按本地增量并「对角钉住」、SVG/HTML 各自输出 transform。
  几何集中在 `renderer/rotation.ts`，手柄命中复用原实现；
- 约束（P5.2）：`constraints` 由运行时在 `node.patch` 里应用（父级尺寸变化 → 子节点按
  贴边/居中/拉伸/缩放重排），父子变更同一条命令、可一次撤销；stack 与 hug 父级跳过；
  拖动父级手柄时画布用同一个 `constrainLayout()` 实时预览，松手不跳；
- 阴影与模糊（P6.1）：`appearance.shadow` 与 `appearance.blur`，无迁移；画布用
  `shadowBlur`/`ctx.filter`，SVG 用 `<filter>` + `feDropShadow`/`feGaussianBlur`，
  HTML 用 `box-shadow`/`filter`，支持矩阵新增 `effects` 行；
- 渐变与文档格式 v3（P6.2）：填充改为 `appearance.fills: Paint[]`（实色 / 线性渐变），
  `CURRENT_SCHEMA_VERSION` 升到 3 并登记 v2 → v3 迁移；`resolveFills()` 收敛所有读取点，
  `gradientLine()` 让画布、HTML、SVG 共用同一套渐变几何；多层填充已接通（画布逐层、
  HTML 倒序 background-image、SVG 逐层图元），面板可增删与切换层；径向渐变
  （`{ type: "radial", cx, cy, r, stops }`）与线性共享色标与几何入口；
- SVG 路径导入（对标 Penpot）：`design-schema/src/svg-path.ts` 按 Penpot 的解析语义
  支持 `M/L/C/Q/A/H/V/S/T/Z` 及小写相对形式与隐式命令，`A`（椭圆弧）用搬来的 MIT
  算法转成贝塞尔；导入产物统一归一化成 `[0,1]` 相对路径，`vector.geometry` 的
  「改宽高即缩放图形」不变式因此继续成立。非法输入让**整条路径作废**，
  不做部分解析；弧线算法与上游逐字节对拍。迁移纪律见 `penpot-porting.md`；
- **Grid 布局**（文档格式升到 v4）：`LayoutSpec.mode` 新增 `grid`，
  轨道配置放在可选的 `layout.grid` 上（`columns` / `rows` 各一组轨道，
  轨道类型有 `fixed` / `fraction` / `auto` / `min-content` / `max-content`），
  子节点占格由 `grid.cells` 按子节点 id 声明（可跨行跨列）。
  `design-layout/src/grid.ts` 求解：测轨道固有尺寸 → fraction 分剩余空间 →
  按单元格定位 → 格子内对齐；子节点超出轨道数时补隐式轨道而非钳位重叠。
  属性面板有轨道编辑器；HTML 导出输出 CSS Grid，SVG/PNG 用解出的绝对盒子。
  v3 → v4 迁移只补版本号与缺省轨道配置，旧文档内容不变。
  **尚未实现**：拖拽调整轨道、命名网格区域、自动轨道。
  差距清单与优先级见 `figma-gap-roadmap.md`；
- 原型交互（**仅数据层**）：`design-schema/src/interactions.ts` 按 Penpot 的
  interactions 语义定义事件、动作、动画与 overlay 定位，节点上以可选
  `interactions` 数组承载，运行时新增 `interaction.patch` 命令（校验语义自洽与
  跳转目标存在性）。**尚未实现**：预览模式、交互状态机、跳转执行、overlay 渲染；
- 仍未覆盖的编辑边界：编组内嵌套子节点的整体移动、跨容器拖拽的自动换父级约束。

本轮已完成的部分：

- 颜色与数值 token 打通到语义层：`resolveRadius` / `resolveGap` / `resolveStroke`
  是唯一解析入口，布局引擎、画布渲染与 HTML/SVG 导出共用；间距 token 覆盖 stack

- 组件生命周期：实例可脱离成普通 frame（子树与物化文字保留，组件定义不动）；

  （`slot.fill`），重复填充先清空，作用范围限制在实例自身、不污染组件定义。
- 实例覆盖：实例选中时列出物化出的文本节点，编辑通过 `component.override` 同步更新

  多选全是实例时提供「批量脱离」。
- 组件变体（component set）：`component.setCreate` 注册只声明属性名的变体集，
  `component.setVariant` 登记成员取值，`component.createVariant` 在命令层复制根子树
  （新 id 用 `${新组件 id}--${源节点 id}`），`component.switchVariant` 让实例切换成员
  （删旧物化子树、重新物化，覆盖按源 id 取交集）；只剩一个成员时集合自动解散。
  组件面板显示变体取值并提供「创建变体」表单，实例面板显示变体下拉框。
  规格见 `component-variants.md`。仍未做：多属性 UI 录入、切换时的覆盖属性映射。

仍未完成：字体 token 的渲染语义、token 分组/别名/主题切换、从样式表或 Figma 导入；

### `0.6.0`：AI 设计闭环

- 范围：至少一个真实 Provider 产品级验证；结构化输出、超时、取消、重试、错误和凭据安全；页面生成、局部修改、结构审查、影响集、审批和回滚。

本轮已完成的部分：

- 失败处理：网络错误与 408/429/5xx 指数退避重试（可配置次数与退避起点），
  超时抛 `AiTimeoutError`、取消抛 `AiCancelledError` 且都不重试；取消信号从工作台
  透传到 fetch，退避等待期间取消也会立刻结束。
- 失败恢复：规划失败或取消不产生待确认计划、不改动项目、事务日志为空，之后可以

- 测试证据：重试、状态码分类、超时、取消、预取消、网络失败预算、失败后项目不变
  与信号透传均有确定性测试。
- 结构审查（Reviewer）：确认前对计划再做一次语义检查——删除锁定节点、删除页面、
  携带 `history.restore` 属于阻断项，`confirm()` 直接拒绝；批量删除、批量新建、
  硬编码填充色属于警告。审查结论带节点 id，工作台在确认卡片里列出并禁用提交按钮。
- 流式响应：SSE 逐段解析 `delta.content` 并通过 `onDelta` 回调实时显示；容忍心跳与
  未知事件，缺 `[DONE]` 时按流结束收尾，没有 body 时退回非流式；已输出增量后不再重试。
- 凭据安全：服务地址、模型与启用开关存 `localStorage`，API Key 只存 `sessionStorage`
  （无会话存储时退化为内存）；旧版本落在 localStorage 的密钥会在读取时迁到会话存储
  并从磁盘副本抹掉；保存空密钥会清除会话密钥。
- 端点能力矩阵：`PROVIDER_PRESETS` 收录 OpenAI、DeepSeek、OpenRouter、Ollama、vLLM、
  LM Studio 的能力差异（json 模式、流式、鉴权），地址匹配做归一化并支持代理子路径；
  未收录端点走保守默认。设置面板显示识别结果与能力标签、支持一键填入预设，
  `jsonMode` 由能力表决定。

仍未完成：真实 Provider 的逐家验收、密钥轮换与作用域管理；结构审查尚未覆盖跨页面

  同一个 `StudioProject`（文件系统仓库）；默认需要人工确认，没有确认渠道时返回
  `approval_required` 而不是执行，审计写 stderr、stdout 只留协议消息。

- HTTP 传输：`npm run mcp:http` 暴露 `POST /mcp` 与 `GET /healthz`，Bearer token 鉴权，
  `initialize` 下发 `Mcp-Session-Id`、会话按空闲过期、同会话请求串行，请求体 256 KB 上限。

仍未完成：OAuth / 多租户隔离、SSE 服务端推送、外部素材服务策略。

## 6. 版本状态维护规则

每次影响 Studio 能力的合并必须：

1. 在本文件对应版本下更新状态；新增功能必须有归属版本。
2. 同步更新 `docs/current-project-status.md`；后者描述“现在有什么”，本文描述“每个版本交付什么”。
3. 更新受影响包的测试和支持矩阵，不得用架构草案代替实现证据。
4. 发布前运行已经启用的构建、单元、端到端、视觉和性能门槛。
5. 生成版本说明，列出新增、修复、限制、数据迁移和破坏性变更。
6. 所有 Studio 包同步到目标版本，更新锁文件，创建 `studio-vX.Y.Z` tag。
7. 发布完成后才标为“已完成”；仅合并代码不代表版本已发布。

统一状态词：

- **规划**：范围已定义，尚未进入版本开发。
- **进行中**：已有实现，但至少一项必需范围或发布门槛未完成。
- **候选**：功能冻结，必需范围完成，正在稳定性验收。
- **已完成**：发布门槛通过，版本说明和 tag 已创建。
- **延期**：从当前版本移出，并明确新的归属版本。

## 7. 当前风险与版本依赖

| 风险 | 最早解决版本 | 处理原则 |
| --- | --- | --- |
| 包版本与实际进展脱节 | `0.1.0` | 建立同步版本、tag 和发布说明流程 |
| Schema 变化令旧项目不可读 | `0.2.0` | 连续迁移、备份、失败回滚和 fixture 测试 |
| DOM 画布的大文档性能 | `0.4.0` | 先建基准，再决定虚拟化或替换渲染适配器 |
| 字体测量造成画布/导出漂移 | `0.4.0` | 字体加载、测量缓存和跨平台基线 |
| 组件与 token 语义扩张 | `0.5.0` | 冻结 V1 子集，超出范围明确诊断 |
| 模型输出不可信或改动过大 | `0.6.0` | 结构化词汇、dry-run、影响集、审批和 revision 锁 |
| PNG/外部资源导出不稳定 | `0.7.0` | 隔离预览、资产策略和交付测试 |
| Studio 意外依赖 legacy | 所有版本 | 依赖检查与架构测试，禁止引入 legacy/Figma 运行时依赖 |
