# 视觉上下文（截图 → 模型 → 再改图）

> 状态：已交付（2026-11-10）。MiniMax-M3 已实测能看图；其余 Provider 待逐家验收。

## 为什么要有这个

原来 AI 只能看到**文字摘要**——节点树、坐标、尺寸、字号、颜色值。这份摘要够精确，
但它**看不见观感**：挤不挤、齐不齐、留白够不够、两个色块放在一起刺不刺眼。

结果就是模型能算能改，但改出来的东西「数值都对、看着难受」。用户说「太挤了」，
模型在摘要里找不到「挤」这个属性——因为摘要里没有它。

视觉上下文把**当前画面的真实截图**一起发给模型，让它能对「看着如何」发言。

## 截图从哪来

**用同一套 Canvas 2D 渲染器离屏渲染整页**，不走「导出 HTML → 浏览器截图」。

这不是实现偏好，是正确性问题：工作台的画布就是 Canvas 2D 渲染的（混合模式、
背景模糊、蒙版、椭圆渐变这些只有画布才有的效果，导出的 HTML 是另一条渲染路径）。
走导出那条路，模型看到的东西和用户看到的东西**不是一回事**——它照着那张图提建议，
改出来的却不是它看到的。

实现见 `packages/studio-web/src/ai-vision.ts`：

- 画布是固定尺寸的画板（960×680），直接按它渲染，不做视口裁剪；
- 图片节点要真的画出来。资源字节走 `loadAssetUrl()` 取（`blob:` URL），加载不到的
  就画占位框——**一张图读不到不该让整张截图失败**；
- 输出按 `maxSize`（默认 1200）等比缩小：太大费 token，模型也看不清细节。

## 截图与摘要的分工写进了提示

附图时提示里会明确告诉模型两者各管什么（`prompt.ts` 的 `describeAttachedImage()`）：

> 文字摘要给的是精确的节点 id、坐标、尺寸与字号；截图给的是观感——挤不挤、对不对齐、
> 够不够醒目、哪里难看。要改的仍然是摘要里列出的真实节点，用它们的 id 下命令；
> 截图用来判断「改成什么样」，不要凭截图猜 id。

不写清楚会出两种错：要么模型忽略截图（那这功能等于没做），要么模型拿截图里的模糊
印象去改精确数值（比如从图上「看着偏左」去改一个实际没偏的 x 坐标）。

截图段排在文档摘要**之前**：先看到「现在长什么样」，再去读精确数值。

## 传输格式

有图时，`content` 从字符串变成**内容块数组**（OpenAI 兼容的多模态格式），文本块在前、
图片块在后：

```json
{ "role": "user", "content": [
  { "type": "text", "text": "……提示正文……" },
  { "type": "image_url", "image_url": { "url": "data:image/png;base64,……" } }
] }
```

这一步不是可选的：只接受字符串 `content` 的端点会直接报错。

## 端点能力：`vision` 是实测出来的

`ProviderCapabilities` 新增 `vision` 字段，规则和其它能力一样：

- **实测过能看图的端点**才标 `vision: true`（目前是 MiniMax-M3）；
- 没验过的端点**不标这个字段**——不标 ≠ 不支持，只是没证据；
- 面板上「带截图问 AI」开关**只在实测过能看图的端点上启用**。没验过的端点可能支持，
  但发过去大概率报错，不给用户一个注定失败的选项。

## 真实 Provider 验收

`npm run ai:provider:acceptance` 新增两项：

| 检查项 | 判据 | 为什么要有 |
| --- | --- | --- |
| `vision` | 发一张**纯蓝 32×32 PNG**，模型答出「蓝」 | 问颜色而不是问「这是什么图」——颜色是这张图唯一可判定的属性，瞎猜也猜得到「一张图」，猜不到蓝色 |
| `visionPlanRoundTrip` | 仓库提示 + 自己画的样例文档 PNG → 模型回命令计划 → 命令都在词汇表内 → dry-run 通过 | 证明「带图」这条链路真的能驱动产品，而不只是能看图 |

MiniMax-M3 实测结果：

```
✔ vision                模型认出了蓝色
✔ visionPlanRoundTrip   带着图解析出 1 条命令（node.patch），dry-run 通过
```

## 浏览器探针：截图确实是画布上那张图

`npm run visual:vision:probe` 在真实浏览器里跑 `capturePageScreenshot()`，把 PNG 拿回
Node **逐像素核对**（`packages/studio-web/visual/vision-probe.ts`）。

Node 里没有画布，只能验证「没有 DOM 就返回 undefined」这种降级分支；像素对不对
（颜色、位置、图片有没有真画出来）只有真浏览器能回答。核对点：

| 核对点 | 期望 | 说明 |
| --- | --- | --- |
| accent 填充 | `rgb(248,113,113)` | 形状颜色与文档一致 |
| dot 椭圆填充 | `rgb(139,92,246)` | 椭圆不是圆角矩形 |
| card 空白处 | `rgb(255,255,255)` | 画布背景与文档一致 |
| 样图上半 / 下半 | `rgb(14,165,233)` / `rgb(245,158,11)` | **资源字节真的画上去了**——没画出来模型看到的是空框，会以为「这里该放张图」 |
| 缺图占位 | `rgb(228,232,237)` | 一张图读不到，整张截图照样出得来 |
| 限长 480 之后 | 480×340，内容仍在 | 等比缩小不是裁剪 |

两个坑记在这里：

- **必须走 `http://`，不能走 `file://`**。资源字节变成 `blob:` URL，而 `file://` 页面的
  源是不透明的，blob: 图跟它不同源 → 画布被污染 → `toDataURL()` 直接抛
  `SecurityError`。生产环境跑在 http(s) 上，所以探针也用 http。
- **拼 URL 不能多一个斜杠**。`server.url` 自带结尾斜杠，再拼 `/` 会变成
  `//harness-vision.html`——那是个协议相对 URL，`new URL()` 会把 `harness-vision.html`
  当成主机名，于是 404。

## 没做的

- **其它 Provider 没实测**：OpenAI / DeepSeek / OpenRouter / Ollama / vLLM / LM Studio
  的看图能力目前未验证，标为「未实测」，面板上不开这个开关。
- **只截当前页**：不截选区、不截多页拼接、不截缩放后的局部。
- **截图内容没有进设计文档**：截图只是发给模型的一次性上下文，不落盘、不进事务日志。
- **没有视觉回归基线**：像素核对是逐点断言（形状颜色、图片资源、占位框），不是整图
  diff。整图基线会绑死字体与抗锯齿，在不同机器上不可靠。
