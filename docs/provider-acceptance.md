# 真实 Provider 验收

> 状态：工具已交付（2026-11-09）。MiniMax 已实测通过；其余服务待逐家验收。

## 为什么要有这个

能力矩阵以前是「读一遍各家文档 + 人工填表」：写上「支持 json 模式」「支持流式」。
那不是验收，是转述——文档说的和服务实际做的经常对不上，而且没人知道哪一条是猜的。

这个工具把每项能力都**实测**一遍，测出来的结论才进仓库。没实测过的端点，面板会
明确标成「文档推断（未实测）」，不拿没验过的结论当事实卖。

## 怎么跑

```bash
# 密钥只从环境变量读，不写进仓库、不进报告
STUDIO_PROVIDER_BASE=https://api.minimaxi.com/v1 \
STUDIO_PROVIDER_MODEL=MiniMax-M3 \
STUDIO_PROVIDER_KEY=... \
npm run ai:provider:acceptance

# 再测一遍并与仓库里的验收记录对账（不一致就失败）
npm run ai:provider:acceptance -- --verify

# 额外跑一次编排循环，看真实模型能不能照着待修清单改对、能不能收敛
npm run ai:provider:acceptance -- --loop
```

CI 里跑不了（没有密钥），所以它是**本地工具 + 入库的验收记录**这一对。

## 测什么

| 检查项 | 判据 | 为什么要有 |
| --- | --- | --- |
| `models` | `GET /models` 返回 200，且列表里有被测模型 | 端点认不认这个模型 |
| `chat` | 普通对话能返回非空正文 | 接口能不能通 |
| `jsonMode` | 带 `response_format: json_object` 的请求被接受，正文里有可解析的 JSON 对象 | 规划器的输出契约靠它 |
| `stream` | SSE 收到多段带内容的增量 | 界面的实时文本靠它 |
| `planRoundTrip` | **仓库自己的提示** → 模型回复 → 解析成命令计划 → 命令都在词汇表内 → dry-run 落地 | 前四项只证明「接口能通」；这一项才是「这个 Provider 能驱动本产品的 AI 编辑链路」 |
| `vision` | 发一张**纯蓝 32×32 PNG**，模型答出「蓝」 | 问颜色而不是问「这是什么图」——颜色是这张图唯一可判定的属性，瞎猜也猜得到「一张图」，猜不到蓝色 |
| `visionPlanRoundTrip` | 仓库提示 + 一张画着样例文档的图 → 模型回命令计划 → 命令都在词汇表内 → dry-run 通过 | `vision` 只证明「模型能看图」，这一项才证明「模型能看着图给出本产品能执行的命令」 |
| `loop`（可选） | 编排循环跑完，`stopReason` 是 `converged` | 「AI 自己跑」最关键的一问：多轮能不能收敛 |

## 验收查出来的六个真缺陷

这不是走过场——第一次跑验收时它直接失败了，逐条修完才对上。

### 1. 推理前缀污染计划解析

MiniMax 是推理模型，正文长这样：

```
<think>先想一遍…</think>

{"summary": "...", "commands": [...]}
```

原来的解析器扫出**第一个**配平的 JSON 对象就解析——推理里出现花括号时就会取到碎片。
现在改成：先剥掉推理块，再逐个候选地试所有配平对象。

### 2. 命令词汇表的节点模板写错了颜色字段

模板里写的是 `appearance.fill`，真正的字段是 `appearance.fills`（数组）。模型照着
错模板建节点 → 节点**没有填充色**，画布上是空的。

### 3. 工具栏画出来的形状一直没有填充色

`978f57d` 把 `fill` 换成 `fills` 时漏改了 `packages/studio-web/src/main.tsx` 的
`makeNode`——用工具栏画的矩形、椭圆、文字、矢量、布尔组，**都是没有颜色的**。
同一个错还留在演示规划器里。

### 4. 运行时静默接受写错的字段

`node.patch` / `text.patch` 落地时用 `Object.assign`，字段名写错也「成功」——命令
成功、文档没变。编排循环把这种无效改动当成一次进展，反复提交同样无效的东西，
直到被判成震荡。

现在运行时直接报错（`node.patch 里有未知字段 "color"`），并且把旧的 `appearance.fill`
归一化成 `fills`（这批节点已经在磁盘上了，不能让它们打不开）。

### 5. 对比度检查器不认段内样式

模型改文字颜色用的是 `text.patch` + `runs[].style.color`——**这是合法的**，颜色确实
改了。但对比度检查器只看节点的填充色，于是报出一个**已经不成立**的问题；AI 盯着这个
假问题反复改，直到被判成震荡。

现在按段计算：节点填充色打底，`runs` 按区间覆盖，逐段算对比度。

### 6. 编排循环不把「命令跑不通」回喂给模型

dry-run 失败时循环直接收工，模型拿不到「哪里错了」。命令哪里不对是模型自己能改的
问题，直接收工等于白跑一轮。现在把报错回喂给它，让它改一版（每轮默认两次机会）。

## 密钥轮换

密钥在客户端存的是**环**（多把 + 当前下标），不是一把。

- **自动**：请求遇到 401/403（密钥过期、被吊销、额度用尽）时，规划器自动换下一把
  重试；环里的密钥都用过还不行，才把错误抛出去。换钥不消耗网络重试预算，反之亦然。
- **手动**：设置面板里「轮换」按钮切到下一把；也可以指定用哪一把。面板上标着
  「使用中」的那把**就是**下一次请求先用的那把（环的起点就是它，不是永远从第一把开始）。
- **安全属性不变**：密钥只写 `sessionStorage`，关掉标签页即失效；不写进
  localStorage、设计文档、事务日志或导出文件。面板上只显示打码后的头尾。

## 没做的

- **其它服务还没实测**：OpenAI / DeepSeek / OpenRouter / Ollama / vLLM / LM Studio
  的能力结论目前仍来自官方文档，标为「文档推断（未实测）」。
- **没有把密钥落盘**：密钥仍然只活在标签页里，刷新标签页（同一标签页仍在）能留住，
  但关闭标签页就没了。要跨设备可用，需要另做一层「用口令加密后落盘」的方案，
  那是另一个安全设计，没有顺手做。
- **没有真正的服务端密钥吊销**：客户端轮换只是「手里还有旧的那把」，不等于服务端
  已经作废了旧密钥。
