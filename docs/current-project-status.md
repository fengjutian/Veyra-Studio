# 当前项目状态

> 状态日期：2026-11-09  
> 用途：为开发者和 AI 提供当前实现范围的单一事实入口

## 一句话结论

当前项目的唯一开发方向是 **独立 AI Design Studio**。Studio 仍处于 Phase 0，现有代码
只是底层原型，还不是可用的独立设计应用。`0.1.0`（tag `studio-v0.1.0`）与 `0.2.0`
（tag `studio-v0.2.0`）已于 2026-11-09 发布，版本说明与验收清单见
`releases/studio-v0.1.0.md` 与 `releases/studio-v0.2.0.md`；按版本定义，`0.1.0` 只是
**垂直原型**、`0.2.0` 收口的是**文档与项目可靠性**，都不代表生产可用。原 Vibma
MCP-to-Figma bridge 已停止使用，只保留为迁移和行为研究的遗留代码；不得把它作为
产品运行时或新功能后端。

## 当前开发范围

### 独立 Studio 的 Phase 0 基础

- `packages/design-schema`：早期设计文档类型、Schema 与校验；节点校验按 `type` 使用判别
  联合，字段级错误不再被吞成一句 "Invalid input"（例如 `textAlign: "justify"` 会直接
  报出 `nodes.<id>.textAlign`）；文本节点新增可选的 `fontWeight`（100–900）、`fontStyle`、
  `textAlign`、`letterSpacing`，缺省值统一由 `TEXT_DEFAULTS` 兜底，旧文档无需迁移；
  文档格式版本升到 **4**，并提供迁移引擎：`CURRENT_SCHEMA_VERSION` 声明当前版本，
  `MIGRATIONS` 是 `旧版本 → 新版本` 的步骤表（当前登记 v1 → v2、v2 → v3、v3 → v4），
  `migrateDocument()` 把任意来源的数据升级到当前版本，失败抛 `MigrationError` 并带上原始版本号，
  成功则把迁移记录写进文档自带的 `migrations` 历史；`detectSchemaVersion()` 负责判断
  版本，高于当前版本或缺少版本的文档一律拒绝，不猜版本；
- **Grid 布局**（文档格式 v4 新增）：`LayoutSpec.mode` 新增 `grid`，与 `absolute` / `stack`
  平级；轨道配置放在可选的 `layout.grid` 上（`columns` / `rows` 各是一组轨道，
  每条轨道有 `fixed` / `fraction` / `auto` / `min-content` / `max-content` 五种类型），
  子节点占哪一格由 `grid.cells` 按子节点 id 声明（可跨行跨列）。
  `design-layout/src/grid.ts` 是唯一求解入口：测轨道固有尺寸 → fraction 按权重分剩余空间
  → 按单元格定位 → 格子内对齐；子节点超出已声明轨道数时**补出隐式轨道**（CSS Grid 语义），
  不钳位造成重叠。属性面板提供轨道编辑器（类型 / 尺寸 / 权重 / 增删）。
  HTML 导出输出 CSS Grid，SVG/PNG 用布局引擎解出的绝对盒子。
  语义对齐 Penpot 的 grid-layout，见 `figma-gap-roadmap.md`；
  **已实现**：拖拽调整轨道宽度、增删轨道（属性面板的轨道条，规格见 `grid-layout.md`）；
  **命名区域**（`grid-template-areas`，2026-11-09）：`grid.areas` 用「每行一个字符串、
  空白分列、`.` 为空位」表达模板，同名单元格必须构成矩形；`grid.cells` 可以用
  `{ area }` 定位子节点，行列与跨度由区域外接矩形推导，因此改模板时子节点跟着走。
  解析与矩形判定集中在 `design-schema/src/grid-areas.ts`，文档校验、布局求解、
  HTML 导出（`grid-template-areas` + `grid-area`）与属性面板读同一份结果；
  布局求解器本身一行未改。模板行列数必须与轨道数一致，改轨道数时编辑器会把区域
  固化成行列号再丢模板（位置不跳、文档仍然合法）；
  **自动重复轨道**（`repeat(auto-fill|auto-fit, …)`，2026-11-09）：`GridTrack` 新增
  `repeat`（`min` 最小宽度 + 可选 `grow` 均分剩余空间），条数在布局时按
  「先扣掉同轴其它轨道、再按 `min + gap` 整除」展开（上限 24 条），
  `auto-fit` 再被该轴子节点数夹住以收起空轨道；展开结果只有 `fixed` / `fraction`，
  求解器一行未改。hug 容器拿不到确定尺寸，退化成一条固定轨道并产生
  `grid-auto-repeat` 警告（否则 fraction 会塌成 0 宽）。HTML 导出输出
  `repeat(auto-fill, minmax(120px, 1fr))` 这类写法，画布与浏览器用同一套条数公式。
  编辑器里自动轨道只画一个 `min` 宽的占位，不可拖拽；
- **表现层能力**（混合模式 / 椭圆渐变 / 背景模糊）：三项都是**可选字段**，
  文档格式版本不变（仍是 v4），旧文档无需迁移。
  `AppearanceSpec.blendMode` 取值与 CSS `mix-blend-mode` 对齐（16 种）；
  `Paint` 新增 `elliptical`（`cx`/`cy` 是归一化中心，`rx`/`ry` 分别是半轴占盒子
  宽 / 高的比例）；`AppearanceSpec.backgroundBlur` 是背景模糊半径（px）。
  Canvas / CSS / SVG 三处的名字映射集中在 `design-schema/src/blend.ts`：
  CSS 与 SVG 直接用同一套名字，Canvas 需要一张到 `globalCompositeOperation` 的
  翻译表——Canvas 的合成是 Porter-Duff 语义，`hue` / `saturation` / `color` /
  `luminosity` 没有等价物，画布侧**退回 normal 并给出警告**，不画错；
  椭圆渐变在画布上走**离屏合成**（正圆渐变 + 按外接矩形贴回 + 按形状裁剪），
  SVG 用「单位圆 + `gradientTransform`」，HTML 用 `radial-gradient(ellipse …)`；
  背景模糊在 HTML 是 `backdrop-filter`，SVG 是「背景副本 + 裁剪 + 模糊」
  （近似，不含祖先背景），画布侧是「离屏快照 + 模糊 + 按形状裁剪」。
  混合模式在画布上是**图层组语义**：节点连同整棵子树先画进离屏层，
  再作为一个整体与背景混合——Canvas 的合成操作是「就地」的，没有图层组概念，
  分组语义只能靠离屏合成实现。椭圆渐变另有可选 `angle`（旋转角）：
  画布与 SVG 精确（SVG 写进 `gradientTransform`），HTML 因 CSS
  `radial-gradient` 不支持旋转而降级并给出诊断。
  **Canvas 支持全部 16 种混合模式**（实测与 CSS 逐像素一致，
  探针见 `studio-web/visual/blend-probe.ts`）；
  详见 `figma-gap-roadmap.md` §5；
- `packages/design-runtime`：早期命令和运行时原型；`text.patch` 接受并校验上述文本样式字段；
- `packages/design-persistence`：文件系统快照、事务日志、资产存储，以及从最后有效快照
  连续重放已提交事务的崩溃恢复原型；仓库契约收敛为单一入口 `contract.ts`：
  `ProjectRepository` 接口、`ProjectNotFoundError`、快照与事务语义都由它定义，
  文件系统实现与浏览器实现共用 `loadDocumentPayload()`（迁移 + 校验）、
  `replayJournal()`（统一的重放与降级判定）、`assertSavableDocument()`、
  `normalizeAssetHash()`，两边的行为因此不会因为换了存储而改变；两个后端跑同一套
  契约测试（`contract-suite.ts`：快照往返、重放、断档降级、项目列表、删除、日志裁剪、
  资产去重、旧版本迁移）；保留策略统一为最近 10 份快照与 200 条事务，另有
  `pruneJournal()` 主动裁剪；包入口拆成浏览器安全的根入口与
  `@ufira/design-persistence/filesystem` 子入口，node 内置模块不再进浏览器包；
  存储布局也有独立迁移链（`storage-layout.ts`，规格见 `storage-layout.md`）：
  版本常量 + 步骤表 + 逐级迁移 + 迁移历史，文件系统与浏览器两个后端各有一套步骤，
  未来版本一律拒绝；
- `packages/design-layout`：宿主无关的 absolute/stack 布局原型，支持 fixed、fill、hug、
  padding、gap、对齐、文本测量接口和结构化布局警告；文本测量提供确定性的字符宽度估算器
  与宿主可注入的测量契约（`createHostTextMeasurer`），修复了 hug 文本高度不随可用宽度换行
  的缺陷；文本换行后超出自身盒高时会报 `text-overflow` 警告（此前该警告码只声明未产生）；
  文本测量把字重和字间距计入宽度（字距按"每个字符后加一次"、字重 ≥600 视为加粗并放大
  6%），宿主测量契约 `TextMeasurementRequest` 同步带上 `fontWeight`/`fontStyle`/
  `letterSpacing`；
- `packages/design-export`：独立 HTML/CSS 导出原型，保留布局与 CSS Token 语义，并对
  不支持或降级的特性输出诊断；新增独立 SVG 导出，SVG 几何由布局引擎解析，stack、fill、
  hug 语义与画布一致；HTML 导出输出 `font-weight`/`font-style`/`text-align`/
  `letter-spacing`，SVG 用 `text-anchor` + `x` 表达盒内对齐，缺省样式不写进 CSS，
  旧文档的导出结果保持不变；导出支持按选区裁剪：`nodeIds` 只导出选中节点所在的分支
  （选中节点连同子树，以及通往它们的祖先链），`origin` 把导出坐标整体平移，让选区落在
  视口左上角；不传这两个参数时导出结果与原来逐字一致；**React 组件导出**
  （2026-11-10）：新增 `exportPageToReact()`，把一页导出成能进工程的 `.tsx`——
  样式复用 HTML 导出的同一套计算（`nodeStyle`），两边只差序列化，所以渲染结果一致；
  文字内容与图片地址提成 props（带段内样式或段落样式的文字不 prop 化，会记诊断）；
  Token 绑定仍导出成 CSS 变量，变量定义在根元素的 style 上（自定义属性会继承）。
  端到端探针 `npm run visual:react:probe` 在真实浏览器里把导出的组件与 HTML 导出
  各渲染一遍，**逐像素比对，实测 0 像素差异**。规格见 `design-to-code.md`；
  **PDF 导出**（2026-11-10）：`design-export/src/pdf.ts` 是零依赖的 PDF 写入器
  （PDF 本身是文本格式的对象表，不需要库），**每页一张位图**——页面尺寸按 96dpi→72dpi
  换算，位图按 2× 渲染（打印更清楚、尺寸不变），图像数据用原生
  `CompressionStream("deflate")` 压缩（正好是 PDF 的 `/FlateDecode` 要的 zlib 流），
  同样输入产出同样字节。工作台「导出 PDF」导整份文档的所有页面，渲染路径与 PNG
  导出同源（SVG → canvas）。端到端探针 `npm run visual:pdf:probe` 真实下载一份 PDF
  并把图像流解出来，确认里面是设计稿而不是白页。**限制**：图片型 PDF，文字不可选、
  不可搜索；矢量 PDF（内嵌 TrueType、文字可选）未做；
- `packages/studio-application`：串联项目创建、命令事务、日志与快照、恢复、布局和
  HTML/SVG 导出的应用服务原型，并提供不修改真实项目的命令预演入口，作为未来工作台与
  AI Orchestrator 的共同入口；
- `packages/ai-orchestrator`：AI 安全编辑闭环的第一阶段原型，包含可替换 Planner
  契约、临时运行时 dry-run、before/after 预览、影响节点、warnings、取消、显式确认
  提交，以及基于 `baseRevision` 的过期计划拒绝；已实现 OpenAI-compatible
  `/chat/completions` Planner、命令提示、文档摘要和 JSON 计划解析；
- AI 请求的失败处理：网络错误、408/429/5xx 按指数退避重试（默认最多两次，
  可配置），超时抛 `AiTimeoutError`、用户取消抛 `AiCancelledError`，这两类都不重试；
  取消信号从界面一路透传到 fetch（内部 AbortController 与外部信号联动），退避
  等待期间取消也会立刻结束。规划失败或取消不会改动项目——计划只有在 dry-run
  成功之后才进入待确认状态，失败后可以直接重试；工作台在生成过程中提供
  「取消生成」按钮，不再只能等请求超时；
- AI 计划的结构审查（Reviewer）：dry-run 之后再看一遍"该不该改"——删除锁定节点、
  删除页面、包含整篇 `history.restore` 三类直接阻断，`SafeAiEditor.confirm()` 会抛
  `AiReviewBlockedError` 并拒绝提交；大批量删除（>10 个节点）、一次性新建（>20 个）、
  硬编码填充色给警告。结论带节点 id，界面在确认卡片里逐条列出并禁掉「确认提交」；
- AI 流式响应：Planner 以 `stream: true` 请求 `/chat/completions`，按 SSE 逐段解析
  `delta.content`，通过 `onDelta(delta, fullText)` 回调边收边显示；解析时容忍心跳与
  不认识的 `event:` 行，缺 `[DONE]` 也能在流结束时收尾，响应没有 body 时自动退回
  非流式 `text()`。已经开始输出增量的请求不再重试（否则用户会看到重复的半截内容），
  中途取消仍然立即中断；工作台在生成过程中显示实时文本；
- AI 凭据存储：服务地址、模型名和启用开关落在 `localStorage`，**API Key 只写
  `sessionStorage`**，关闭标签页即失效；没有 sessionStorage 时退化为内存保存。
  读取旧版本数据时会把原先写进 localStorage 的密钥迁到会话存储，并把磁盘副本里的
  密钥抹掉；保存空密钥会主动清掉会话里的密钥。密钥不会进入设计文档、事务日志、
  导出文件或 IndexedDB；
- 密钥作用域管理（2026-11-10）：设置面板新增「密钥落盘（口令加密）」区块。密钥环用
  **AES-GCM-256** 加密，密钥由口令经 **PBKDF2-HMAC-SHA256 / 210k 次** 派生，盐 16 字节、
  IV 12 字节均每次随机；磁盘（`localStorage` 的 `studio:ai-key-vault`）上**只有密文**，
  **口令不落盘**、不记「记住口令」。口令错或密文被篡改都解不开（GCM 认证标签），
  界面明说「口令不对（或密文已损坏）」而非静默失败。落盘的是**环**不是一把，换设备后
  多把密钥与「使用中」的那把都还在。加密保存会顺带把密钥应用到当前会话；解锁后密钥
  回到 `sessionStorage`。规格见 `key-vault.md`，端到端由 `npm run visual:vault:probe`
  验证（真实浏览器里配密钥 → 加密 → 刷新模拟换标签页 → 口令错明说 / 口令对回会话）；
- AI 端点能力矩阵：`PROVIDER_PRESETS` 收录 OpenAI、DeepSeek、OpenRouter、Ollama、
  vLLM、LM Studio 的地址、默认模型与能力（是否支持 `json_object`、流式、鉴权方式），
  地址匹配支持大小写/尾斜杠归一化与「官方地址下挂代理」的更深路径；未收录的端点按
  通用协议处理，并保守地关闭 json 模式。设置面板会实时显示识别结果与能力标签，
  并可按预设一键填入地址和模型；`jsonMode` 现在由这张表决定，而不是写死；
- 编排循环（体检驱动的多轮自主运行）：`ai-orchestrator` 新增体检层，把设计 lint、
  对比度与导出诊断聚成一份**带稳定指纹**的报告（指纹 = 来源:代码#节点，不含消息文本，
  所以「同一个问题」跨轮可识别）；再新增编排循环，把「体检 → 计划 → dry-run → 审查
  → 提交 → 再体检 → 再计划」串起来。每一轮把**体检结论回喂给模型**（经
  `AiPlanRequest.selfCheck` 拼进提示的 user 段，排在文档摘要之前），所以第二轮之后
  模型拿到的不是需求复读而是「哪里还不对」。停止条件显式九种：收敛 / 轮次用完 /
  结构审查阻断 / 审批否决 / 模型没给命令（`PlanEmptyError`，与故障分开）/ 模型故障 /
  提交失败 / 取消 / 震荡；同一个指纹连续出现 3 轮判定为修不动并从待修清单剔除，
  待修项全判死时以「震荡」收尾，不烧满轮次。每轮走正常事务因此可逐轮撤销。
  工作台 AI 分段新增「自主运行」入口与轮次日志。规格见 `autonomous-loop.md`；
- 真实 Provider 验收：`npm run ai:provider:acceptance` 把端点能力从「照文档抄的表」
  变成**实测结论**——逐项测 `/models`、普通对话、`response_format: json_object`、
  SSE 流式，以及最关键的**规划器往返**（仓库自己的提示 → 模型回复 → 命令计划 →
  dry-run 落地）；`--verify` 与仓库里的验收记录对账，`--loop` 额外跑一次编排循环看
  真实模型能不能收敛。密钥只从环境变量读，不进仓库也不进报告。已实测通过的端点
  （目前是 MiniMax）把结论写进 `packages/ai-orchestrator/src/provider-acceptance.ts`，
  能力矩阵以**实测**优先于预设；没实测过的明确标成「文档推断（未实测）」。
- 密钥轮换：客户端存的是**密钥环**（多把 + 当前下标），不是一把。请求遇到 401/403
  （过期、被吊销、额度用尽）时规划器自动换下一把重试，环里都用过还不行才报错；换钥
  与网络重试是两套预算，互不消耗。设置面板可加多把、删某把、手动轮换，密钥仍只落
  `sessionStorage`，面板上只显示打码后的头尾；
- 验收查出并修掉的真实缺陷（2026-11-09）：推理模型（MiniMax-M3）的 `<think>` 前缀会
  污染计划解析；命令词汇表的节点模板把颜色写成不存在的 `appearance.fill`；工具栏画
  出来的矩形/椭圆/文字/矢量**一直没有填充色**（`978f57d` 改 `fill`→`fills` 时漏改
  `main.tsx`）；运行时用 `Object.assign` 静默接受写错的字段（字段名写错也「成功」但
  文档没变，编排循环会把无效改动当成进展）；对比度检查器不认段内样式 `runs`，报出
  已经不成立的问题；编排循环不把「命令跑不通」的报错回喂给模型。现在运行时对未知
  字段直接报错、并把旧 `appearance.fill` 归一化成 `fills`。规格见

  `remapTextRuns()`，按公共前后缀平移区间，段首插字不会让加粗整体错位。
  换行统一由 `design-layout` 的 `layoutRichText()` 决定（按空格优先断行、行尾空格不计宽），
  画布、估算测量器、浏览器 Canvas 测量器、测量缓存键全部共用它，避免「画布 3 行、
  布局以为 2 行」；画布逐段设置字体与颜色，HTML 输出 `<span>`、SVG 输出 `<tspan>`，
  没有 runs 时导出产物与升级前逐字一致（视觉基线仍是 0 差异）。
  属性面板的多行文本框会记录选区，选中文字后改粗细/字形/选区字号/选区颜色只作用于选区，
  「清除选区样式」恢复节点级样式。规格见 `rich-text.md`；
  **尚未实现**：段内行高覆盖；
- **画布内联编辑（样式可视化）**：双击文本进入的编辑层不再是纯 `<textarea>`，
  而是**结构化 `contenteditable`**——每个段落是一个块，段内 run 按样式渲染成
  `<span>`（字重/字形/字号/颜色），列表段落带标记（`contenteditable=false` 的
  `•`/编号，右对齐在标记区里）与缩进。因此编辑时能看到真实样式，而不是
  「一段均匀的纯文字」。正文起点与画布的 `left` 完全一致（级别缩进 + 标记区宽度）。
  DOM 是**不受控**的：内容被用户直接改写，React 不再回写 children（否则每键重建
  DOM、光标丢失），提交时从 DOM 还原文本（段落边界与 `<br>` 还原成 `\n`，
  标记元素跳过）；段内 `runs` 与段落 `paragraphStyles` 不由编辑器产生，
  文字变了没给新样式时由运行时的 remap 对齐。
  交互规则不变：`Enter` 提交、`Shift+Enter` 换行、`Esc` 取消、失焦提交。
  规格见 `inline-text-editing.md`；
  **尚未实现**：编辑器内直接改样式（加粗/变色/列表/缩进仍走属性面板）、
  编辑期间属性面板改样式不实时反映到编辑器、编辑态不显示混合模式等节点级效果；
- **富文本段落样式（列表 + 缩进）**：`TextNode.paragraphStyles?: ParagraphStyleRun[]`
  用「对齐段落边界的 UTF-16 区间 + 样式」表达「这一段是列表项 / 缩进几级」，
  可选字段，旧文档不迁移（文档格式版本仍是 v4）。区间必须整段覆盖且互不重叠——
  段落样式描述的是「整个段落长什么样」，允许半段覆盖会让「这段算不算列表项」变模糊。
  编号**不存进文档**：渲染期按段落顺序现算（数字 → 字母 → 罗马，随级别循环），
  两段独立的列表各自从 1 开始，插行删行不需要迁移数据。
  命令 `text.paragraph.set` 把区间**吸附到段落边界**（在列表项中间选一个字，整项都变，
  与 Figma 一致），样式是**增量**语义，`listType: "none"` 取消列表，
  `indentDelta` 是相对缩进（每一段按自己级别加减，对应 Tab / Shift+Tab）。
  文本被改写却没给新样式时走 `remapParagraphStyles()`：按「字符是否还在」重新对齐，
  段落被换行劈开时两段都继承样式，整段被删时样式一起消失。
  画布在段落首行画标记（编号右对齐在正文左侧一个间隙处）、正文按缩进右移，
  缩进会吃掉可用宽度所以「加一级缩进」真的让文字提前换行；
  HTML 输出真正的 `<ul>/<ol>`（编号用 `<li value>` 显式给值，与画布一致），
  SVG 的标记与正文分属两个 `<text>`。属性面板「文字」区新增「段落」小节
  （列表类型分段控件 + 缩进步进器 + 段落缩进 + 悬挂 + 列表间距）。规格见 `paragraph-styles.md`；
  **段落缩进（px，Figma 的 Paragraph indent）、悬挂列表、列表间距已实现**：
  段落缩进只对左对齐生效（居中/右对齐时画布会扣掉它），悬挂列表的标记不占正文宽度、
  画在文本框外（画布的裁剪区往左让出标记的宽度），列表间距加在段落之后；
  **尚未实现**：一个节点内混排多种列表类型；
- **字体管理**：字体文件走与图片同一套资产管线（SHA-256 落库、去重、随文档备份），
  `document.fonts` 记录族名 + `assetId`（缺省表示依赖系统字体）+ 字重/字形，可选字段、
  旧文档不迁移。`font.register` 同键替换、`font.remove` 在族名仍被文本使用时拒绝，
  `asset.delete` 也会保护字体引用的字节。加载侧 `loadDocumentFonts()` 用 FontFace API
  注册上传文件，`prepareFonts()` 返回真正可用的族名，`collectMissingFonts()` 得出
  「文本用到但没有任何来源」的族名——在「数据 → 字体」里用橙色提示条明确列出，
  不再静默回退。属性面板的字体输入带 datalist 建议（已加载 + 文档声明过的族名）。
  规格见 `font-management.md`；
  **字体 token 的渲染语义已实现**（2026-11-09）：`TokenValue` 新增 `typography`
  （族名 / 字号 / 行高 / 字重 / 字形 / 字距），绑定到文本节点后覆盖上述字段，
  **省略的字段不覆盖**节点值。`applyTypographyToken()` 是唯一入口，布局测量、
  画布场景、HTML/SVG 导出与导出字体内联都在这里汇合；schema 拒绝把字体 token
  绑到非文本节点、也拒绝用颜色/数值 token 充当字体；
- **字体度量基线已建立**（2026-11-09）：`design-layout/src/font-baseline.ts` 定义固定
  样例集（中英文混排、纯中文、字重、斜体、字距、固定宽度下的换行）与比较逻辑；
  采集端 `studio-web/visual/font-baseline.ts` 用 esbuild + headless Chrome 跑
  **编辑器同一条测量路径**（`createBrowserTextMeasurer()`），结果写进 DOM 再读回。
  基线文件记录**平台指纹**（系统 / 浏览器 / 采样时间），换机器时差异是可解释的。
  判定纪律：宽度容差 0.5px、**换行点零容差**、**非有限值一律算差异**（含 NaN 的
  基线曾被判成"完全一致"，因为 `NaN === NaN`）。仓库里目前只有 Windows + Chrome
  这一份基线，其余平台要各自采集。规格见 `font-baseline.md`；
- **导出物内联字体**：HTML 交付物会把**文档声明过**的字体文件内联成
  `@font-face`（data URI），因此对方机器上没装这个字体也不会走回退字形——
  「画完了、交出去、字变了」这个断链被接上了。规则：只有 `document.fonts` 里
  带 `assetId` 的族名才内联（系统字体不需要），每个 `(族名, 字重, 字形)` 一条规则，
  字重找不到精确匹配时回退同族名的另一条并记 `approximated` 诊断；
  字体文件超过 1 MB 不内联，改为一条写清后果的诊断（base64 会让体积涨约 33%）。
  上传字体时还会读出文件里的真实族名与字重（`fonteditor-core` 动态加载，
  读不出来才回落文件名猜测），不再让用户靠文件名猜。
  规格见 `font-inline.md`；
  **字体子集化已实现**（浏览器端 harfbuzz wasm：超过 1 MB 的字体先裁到导出范围里
  真正用到的字符再内联，规格见 `font-management.md` §7）；
  **SVG 导出的字体内联已实现**（2026-11-09）：SVG 交付物此前和 HTML 一样只带
  `font-family`、不带字形，现在与 HTML **共用同一套**字体准备逻辑（收集 / 匹配 /
  1 MB 阈值 / 子集化 / 诊断），差别只有落点——规则写进根 `<svg>` 下的一个 `<style>`。
  先实测再实现：新探针走真实导出路径，覆盖顶层 `.svg` 文档、HTML 内联 `<svg>`、
  `<img src="…svg">` 三种加载场景，文字宽度都从 483.6px 变成 912px
  （Press Start 2P 的等宽步进），探针已并入 `npm run check:visual`。
  顺带修掉一个**老 bug**：SVG 导出写 `font-family` 时不加引号，
  `Press Start 2P` 这类含数字的族名会让整条声明作废（`2P` 不是合法 CSS 标识符），
  导出的 SVG 根本用不上声明的字体；现在只在必要时加引号，裸写时旧产物逐字不变。
  字体内联也按字体 token 生效后的族名/字重收集，不会出现「设计稿用了 token、导出物却没内联」；
- 图片资产闭环：可从本地插入 PNG/JPEG/GIF/WebP/SVG 图片，字节按 SHA-256 写进仓库并去重，
  文档里先登记资源元数据（`asset.upsert`）再在同一个事务里创建 `image` 节点，两步不会
  只成一半；画布按 `fit`（覆盖/适应/拉伸）用对象 URL 渲染，资源缺失时画占位框并标注
  「图片资源缺失」，不会留一个空白；HTML/SVG/PNG 导出都会把图片内联成 data URL，
  PNG 光栅化因此不再被外部资源污染画布；导入别人的 JSON 时会逐份核对资源是否在本地
  存储里，缺失的数量和名字写进状态提示，也单独列进恢复报告；
- 资产**读路径**对非法哈希宽容：导入的文档里资源哈希不是合法 SHA-256 时，
  `getAsset` / `deleteAsset` 按「读不到」处理（返回未找到 / 什么都不删），不再抛
  「Asset hash must be a SHA-256 hex string」把整条导出打断；**写路径**保持严格
  （`putAsset` 仍然校验哈希与字节一致）。此前一份改过的导入文档只要带一张这样的图，
  导出就会整条失败；
- 「数据」分段列出**图片资源**：列出每份资源的大小、被几个图片节点引用，以及是否缺失；
  缺失资源可以「重新关联」——只接受内容哈希一致的原文件，补字节不动文档，所以已经
  渲染出来的缺失节点会立刻恢复，revision 也不会因为补文件而上涨；没有被引用的资源
  可以清理，元数据走 `asset.delete` 进入事务，字节在没有别的记录共享同一个哈希时才
  从仓库删除；
- 图片节点可以整张替换：「替换图片…」把新图按哈希落库、登记元数据，再用
  `image.patch` 把节点的 `assetId` 指过去，节点 id、位置、尺寸和 `fit` 都不变，
  因此选中状态、布局和撤销历史都不会断；换图与换 `fit` 共用同一条
  `image.patch`，指向未登记的资源会被命令层拒绝；
- 存储用量面板：读取 `navigator.storage.estimate()`，给出已用/额度、百分比和进度条，
  70% 提示、90% 告警，并给出「导出 JSON 备份」和「清理旧项目」两条出路；
  环境不支持估算时显示「无法获取」而不是报错；
- 自动备份与轮转：每次自动保存落盘后最多每 10 分钟写一份完整文档备份，按项目保留
  最近 3 份（独立于快照和事务日志的 IndexedDB 库）；面板可以下载任意一份为 JSON，
  也可以还原——还原沿用 `history.restore`，revision 继续递增、可再撤销；删除项目
  会连它的备份一起清掉；
- 磁盘备份（2026-11-09）：另有一路写到用户选的本地目录（File System Access API），
  5 分钟节流、每项目保留 10 份、只轮转自己写的文件；文件名带项目/时间戳/revision，
  JSON 可直接拖回导入；规格见 `backup.md`；
- 工作台可下载当前页面的独立 HTML、SVG 交付物和当前项目 JSON 备份，并报告导出诊断数量；
  PNG 交付物由 SVG 经浏览器 Canvas 光栅化生成；
- 导出诊断面板：最近一次导出的每条诊断都列成一行（特性、支持程度、原始说明），
  带节点 id 的诊断可以点击直接选中对应节点；面板里还有一张随导出器一起维护的
  **支持矩阵**（`EXPORT_SUPPORT_MATRIX`：绝对/自动布局、尺寸策略、文字样式与换行、
  Token、基础形状、图片、组件实例、矢量、隐藏节点、PNG 光栅化），逐项写明在
  HTML / SVG / PNG 三种交付物里的支持程度。矩阵和诊断共用同一套特性 id，并有测试
  保证导出器发出的每一种诊断都能在矩阵里找到对应行。组件实例的覆盖有单独的
  `component-override` 诊断（说明这个实例导出了几个被覆盖的节点），和"实例只导出
  物化子树"的近似诊断分开显示；
- 导出基线（golden files）：`design-export` 的测试里锁住了 HTML 交付物、SVG 交付物、
  选区导出产物和布局包围盒——字体走纯字符估算器，因此结果跨平台确定。任何无意的
  几何、CSS 或 token 变量变化都会变成测试 diff；确认改动后用 `UPDATE_GOLDEN=1` 重新
  生成基线。这套基线当场抓到一个真缺陷：SVG 导出给 token 变量多补了一个 `--` 前缀，
  写成 `----color-primary`，而节点引用的是 `var(--color-primary)`，颜色在 SVG 里静默
  失效；已修复并补了专门断言定义与引用两侧的测试；
- 隔离预览：诊断面板旁可以「预览 HTML / SVG / PNG」。HTML 交付物渲染在
  `sandbox=""` 的 iframe 里（不执行脚本、不给同源权限），SVG 和 PNG 走 data URL 的
  `<img>`；预览和下载用的是同一次导出的产物，不会出现"预览好看、下载走样"；
- 导出范围可切「整页 / 选区」：选区导出用选中节点的包围盒作为视口，只导出与选中节点
  相关的分支，文件名和状态文案都会标注范围；选区为空时自动退回整页；
- **资产打包**（2026-11-09）：交付物不再只有「单个自包含 HTML」——「导出」分段新增
  「导出资源包」，把图片与字体拆成独立文件（`assets/`、`fonts/`），主文档用**相对
  路径**（`./assets/…`）引用，整个目录打成 ZIP 分发。体积不涨（内联要付 33% 的
  base64 代价），字体也**不再受 1 MB 内联上限约束**。导出器一行没改（`./` 开头的
  相对路径既有的 URL 白名单本来就接受）；资源名里的路径分隔符、`..`、前导点全部
  清掉；ZIP 自己写（store 模式、时间戳固定，零新依赖）。限制：SVG 与 PNG 交付物
  继续走内联（`<img>` 引入的 SVG 访问不到外部资源，PNG 光栅化也没有相对路径基准），
  资源包不能预览（相对路径要落盘后才解析得了）。规格见 `asset-packaging.md`，
  端到端由 `npm run visual:package:probe` 守着：真实应用里插真 PNG → 下载 ZIP →
  读回来核对条目、引用与图片字节；
- **版本并排对比**（2026-11-09）：「导出」分段有独立的「版本对比」区，列出存储保留的
  历史版本（当前版本除外——自己跟自己比没有意义），点「和当前版本并排对比」打开两栏
  预览：左栏历史版本、右栏当前版本，两侧标题写清是哪一版（标签 + 时间）与「当前」。
  两侧走**与真正下载完全相同的导出路径**（同一页、同一批节点、同一视口），所以看到
  的就是交付物本身。范围对不上时不静默换范围：历史版本里没有当前这一页就说「没法并排
  对比」，选中的对象在历史版本里缺一部分就说少了几个，一个都没有就退回整页并说明。
  范围计算是纯函数（`studio-web/src/version-compare.ts`，9 项单测），端到端由
  `npm run visual:compare:probe` 守着：导入 fixture → 真实按键挪动节点（产生第二个
  版本）→ 点开对比 → 逐点比对两栏内容，确认左栏是改动前、右栏是改动后，并确认历史
  缺页时应用说清楚而不是摆出两幅不相干的画面；
- 编辑器外围补齐四项：① 多选时可批量改文字样式（字体/字号/行高/粗细/字形/对齐/字距），
  只作用于选中的文本节点，逐条走 `text.patch`，值没变的节点不发补丁；② 图层面板支持按名称或文本内容
  搜索，命中项的祖先层同样保留可见，搜索时自动展开折叠的层级；③ 左右面板可折叠，
  收起后画布拿到全部宽度；④ 画布支持抓手平移（工具栏切换，或按住中键拖动），平移只改
  视口滚动位置，不写文档也不涨 revision；
- 对应包已有有限的单元测试，并被根级 `build:studio-core` 和
  `test:studio-core` 脚本覆盖。

这些包证明部分领域边界可以脱离 Figma，但不构成完整产品。

## AI 操作规则

- 回答“项目目前是否支持某功能”时，必须先检查源码、测试和构建脚本，不能只引用架构稿；
- 不得把目标目录树描述成当前目录树；
- 不得宣称独立 Studio 已经完成；
- 不得建议用户启动 Vibma relay、导入 Figma 插件或配置旧 MCP Server；
- 只有明确的遗留迁移任务才允许修改 bridge，并继续遵守其既有边界；
- 修改独立 Studio 原型时，不得引入 Figma、React、MCP SDK 或具体 renderer 到
  `design-runtime`；
- 新增已实现能力后，应同步更新本文，避免状态文档再次落后。

## 当前验证命令

独立 Studio 底层原型：

```bash
npm run build:studio-core
npm run test:studio-core
npm run bench:layout
npm run build:studio-web
npm run test:studio-web
```

端到端探针（对着**构建产物**跑真实界面，需要本机有 Chrome/Edge）：

```bash
npm run visual:compare:probe   # 版本并排对比
npm run visual:package:probe   # 资源包交付
npm run visual:loop:probe      # 编排循环（自主运行）
npm run visual:mcp:probe       # MCP HTTP 传输（OAuth / 多租户 / SSE），不需要浏览器
```

本地启动 Web 垂直切片：

```bash
npm run dev:studio-web
```

这些命令成功仅表示底层包能够构建并通过已有测试，不表示独立 Studio 已经可运行。

上述构建、测试与 `npm run check:budgets` 已由 `.github/workflows/studio-ci.yml` 在
push / PR 上执行；视觉回归（`npm run check:visual`）单独成 job 且允许失败，因为产物
基线绑定本机字体，Linux runner 上的像素差异来自字体而不是代码。legacy Vibma 的发布
仍走 `release.yml`，与 Studio 无关。

不要把 `npm run socket`、Figma 插件安装或 Vibma MCP 配置作为本项目的运行步骤。
