# 磁盘备份

> 文档状态：生效中的实现规格
> 建立日期：2026-11-09
> 关联文档：`current-project-status.md`、`project-progress-and-version-roadmap.md`（`0.2.0`）

## 1. 为什么还要磁盘备份

现有的三层保护都困在同一个浏览器里：

| 机制 | 解决什么 | 仍然怕什么 |
| --- | --- | --- |
| 事务日志 + 快照 | 崩溃恢复、撤销/重做 | 存储损坏 |
| 历史版本 / 重建基线 | 回滚到旧版本、回退到某一步 | 误删项目 |
| IndexedDB 自动备份 | 覆盖前留三份完整文档 | 清空站点数据、换浏览器、换机器 |

磁盘备份把完整文档写进用户自己选的目录：能跨浏览器、能进网盘/同步盘、
能直接拖回编辑器导入。加密与跨设备同步**不在范围内**——前者需要密钥管理，
后者需要服务端；同一份 JSON 放进用户自己的同步目录已经覆盖了大部分需求。

## 2. 分层

```
disk-backup.ts          纯逻辑 + 可注入的目录端口（Node 里可测）
        ↑
disk-backup-browser.ts  File System Access API：选目录、权限、句柄持久化
        ↑
disk-backup-panel.tsx   面板：备份到哪、上次何时、立即备份 / 断开
        ↑
main.tsx                自动保存落盘后触发；目录句柄跨会话恢复
```

## 3. 纯逻辑

`DiskBackupRunner` 不抛错：自动保存链路上的备份失败不能把编辑器带崩，
失败写进状态由界面展示，且**不推进** `lastSavedAt`（下一次自动保存会重试）。

- **文件名**：`ufira-backup-<项目片段>-<UTC 时间戳>-r<revision>.json`。
  项目 id 折成 `[A-Za-z0-9._-]`，其余字符压成一个 `-`。时间戳定宽（`20261109T121957Z`），
  所以按文件名字典序排就是按时间排，轮转不需要读文件内容。
- **节流**：默认 5 分钟，第一次立即写；「立即备份」按钮用 `force` 绕过节流。
  与 IndexedDB 备份（10 分钟）各自独立：一边跳过不影响另一边。
- **轮转**：每个项目只保留最近 10 份。只处理**本项目**的备份文件——
  目录里用户的别的文件、别的项目的备份一律不碰。删文件不可逆，不能手滑。
- **状态**：`idle` / `disabled` / `throttled` / `saved`（带文件名与份数）/ `error`（带原因）。

## 4. 浏览器实现

- 只有 Chromium 系支持 `showDirectoryPicker()`；Firefox / Safari 上面板直接说明
  不支持，并指向「导出 JSON 备份」这条退路，而不是给一个点了没反应的按钮。
- 目录句柄可以结构化克隆，存在独立的 IndexedDB 库（`ufira-design-studio-fs`）里，
  下次打开自动恢复。
- **权限不能跨会话自动恢复**：页面加载时只能 `queryPermission()`，
  `requestPermission()` 必须发生在用户手势里。因此权限被收回后，
  要么重新点「立即备份」，要么重新选目录——界面不会偷偷弹权限框。
- 写入走 `createWritable()`（临时文件 + 原子替换），不会留下半截 JSON。
- 用户取消选择器（`AbortError`）是正常路径，不报错。

## 5. 验收

- 纯逻辑：文件名往返解析、非备份文件识别、轮转只删本项目最旧文件、
  节流边界、force 绕过、写入失败转状态且不推进时间、跨会话恢复节流。
- 手工（Chromium）：选目录 → 首次立即写一份 → 5 分钟内再保存不写 →
  「立即备份」立刻写 → 超过 10 份时最旧的被删 → 刷新页面后目录仍在、
  上次备份时间仍在 → 清空浏览器存储后目录里的文件仍在。
- 非 Chromium：面板显示不支持说明，不出现可点击但无效的按钮。

## 6. 仍未完成

- **加密**：备份是明文 JSON，落在用户选的目录里（信任边界＝用户自己的磁盘）。
- **跨设备自动同步**：依赖用户自己的同步盘；没有账号、没有服务端。
- **定时后台备份**：只在自动保存真正落盘后触发；页面关闭时不会为了备份而阻塞。
